## Структура проекта

- `public/shows/<slug>/files` — pdf/png/zip материалы спектакля
- `public/shows/<slug>/photos` — изображения для галереи и карусели
- `public/shows/<slug>/images` — фоновые изображения
- `public/shows/<slug>/data` — YAML-расписание (используется на клиенте)
- `shows/<slug>` — конфиг спектакля: тексты на трёх языках и ссылки на ассеты
- `components/ShowLandingClient.tsx` — универсальный клиентский компонент страницы
- `app/[show]/page.tsx` — главная выбранного языка (`/ru`, `/he`, `/en`)
- `app/[show]/[slug]/page.tsx` — страницы спектаклей на постоянных языковых адресах
- `components/TheatreHome.tsx`, `lib/homeCopy.ts` — главная и переводы
- `lib/i18n.ts`, `proxy.ts` — выбор языка и совместимость старых ссылок

## Расписание (автоматизация)

- Редактирование CSV и генерация YAML: `docs/schedule-automation.md`.
- Google Sheets + кнопка обновления: `docs/google-sheets-sync.md`.

Корневая `/` открывает главную на языке браузера. Адреса `/zlata`, `/marita` и `/gefilte-lid` также автоматически выбирают доступный язык. Явный `?lang=ru|he|en` и сохранённый вручную выбор (`preferredLang` cookie) имеют приоритет перед заголовком `Accept-Language`.

Постоянные адреса языковых версий:
- `/ru`, `/he`, `/en` — главная (русский, иврит, английский).
- `/ru/zlata`, `/he/zlata`, `/en/zlata` — «Козочка Злата».
- `/ru/marita`, `/en/marita` — «Колдовство Мариты».
- `/ru/gefilte-lid`, `/en/gefilte-lid` — «Гефилте Лид».

Явный языковой адрес никогда не переключает текст по настройкам браузера. При запросе иврита для спектакля без ивритского перевода используется английский. Без языковых предпочтений запрос открывает русскую версию; для остальных неподдерживаемых языков используется английский. Язык страницы не изменяет язык самого представления — он указан в расписании.

Автоматический выбор использует временный `307`, `Vary: Accept-Language, Cookie` и `Cache-Control: private, no-store`. Параметры ссылки сохраняются; фрагмент `#schedule` наследуется браузером при редиректе. Переключатели языка сохраняют параметры и фрагмент. Sitemap перечисляет только существующие языковые страницы, каждая содержит свой canonical и взаимные hreflang, включая x-default на общий входной адрес.

Проверка совместимости языковых маршрутов и возвратов после оплаты:

```bash
node --import tsx --test tests/i18n.test.ts tests/afisha.test.ts
npm run build
```

## Домены и proxy

Основной production-домен: `https://ryba-kiva.com`.

В `proxy.ts` заведён маппинг старых доменов на страницы спектаклей:

```ts
const HOST_TO_SHOW = {
  'www.ryba-kiva-zlata.com': 'zlata',
  'www.ryba-kiva-marita.com': 'marita',
};
```

Старые публичные страницы отдают постоянный `308`-редирект на соответствующий маршрут основного сайта. Пути `/api/*` на старых доменах временно остаются доступными для callback-запросов ранее созданных платежей. Для локальной разработки используются `localhost` и `127.0.0.1`.

Новые домены для отдельных спектаклей не добавляются. Все спектакли публикуются внутри `ryba-kiva.com/<slug>`.

## Добавление нового спектакля

1. Создай `public/shows/<новый_slug>/{files,photos,images,data}` и положи туда контент.
2. Добавь `shows/<новый_slug>/content.ts` (тексты на трёх языках) и `shows/<новый_slug>/index.ts` (описание ассетов).
3. Экспортируй конфиг в `shows/index.ts`, обнови `ShowSlug`.
4. Проверь страницу по адресу `https://ryba-kiva.com/<новый_slug>`.

## Афиша и прошедшие показы

На главной и на страницах спектаклей показываются все будущие представления. Если их меньше восьми, список дополняется самыми недавними прошедшими показами до восьми записей (или всеми доступными, если записей меньше восьми). Будущие показы идут по возрастанию даты, затем прошедшие — от новых к старым. Начало представления определяется по дате и времени в часовом поясе Asia/Jerusalem.

У прошедших показов отображается отметка о завершении вместо покупки билета; встроенные ссылки на старые кассы также становятся обычным текстом. Рабочая база расписания остаётся основным источником. Резервные public/shows/<slug>/data/schedule.yaml обновлены по опубликованному расписанию сайта, чтобы история оставалась доступной и без подключения к базе.
